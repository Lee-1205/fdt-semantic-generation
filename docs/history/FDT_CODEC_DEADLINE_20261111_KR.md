# 문장 복원 코드와 데이터 점검

목표는 11월 12일 0시 전까지 언어 → 의미 → 언어 복원을 검증하는 것이다. 기존 세 메모리와 Commit 경계를 유지하며, 복원이 안정화된 뒤 답변 의미를 만드는 디노이징 단계로 진행한다.

V45의 학습 16,384구간을 원래 학습 문서와 대조했다. 새 구간은 문서 및 구간 번호와 일치했고, 기존 구간은 각 학습 문서에서 네 구간이 연속으로 저장된다는 가정과 일치했다. 모든 입력이 같은 문장을 정답으로 사용하며, UTF-8 바이트와 종료기호가 일치했다. 정규화 후 학습과 개발 문장 사이 중복은 0건이었다. 학습 세트 내부에 정규화상 중복 1건이 있었다. 구조 변경을 비교하기 위해 V46에는 V45와 같은 데이터와 순서를 사용한다.

| 자료 | 행 | 중앙값, UTF-8 바이트 | 10–90백분위, 바이트 |
| --- | ---: | ---: | ---: |
| 학습 | 16,384 | 90 | 57–121 |
| 전체 개발 | 256 | 89 | 55–122 |
| 기존 직접 복원 개발 패널 | 16 | 97.5 | 73–125 |

V46에서는 기존 16구간을 유지하고, 개발 문서 64개에서 한 구간씩 BOS부터 복원한다. 복원은 바이트 일치와 종료기호로 확인하며, 인명·수치·관계·부정이 빠졌는지는 원문과 실제 출력을 대조한다. 같은 256구간의 정답 접두사 평가도 비교에 쓴다.

V45 디코더는 두 의미 벡터에 같은 종류 임베딩을 붙인다. 출력 토큰에는 위치 임베딩이 있고, 입력 의미 벡터에는 슬롯별 위치 태그가 없다. 저장한 벡터로 실제 CPU 디코더를 호출했을 때, 한 문장의 두 벡터를 뒤집으면 첫 바이트 로짓의 최대 변화가 0.0000076이었고 다른 문장의 벡터를 넣으면 33.475였다.

V46은 기존 두 의미 벡터에 앞뒤 구간의 퍼지 읽기와 디코더 슬롯 태그를 더한다. 추가 파라미터 1,026개를 0으로 초기화한다. 기존 V45 모델·91개 Adam 상태·스케일러·저장 RNG를 가져온다. 초기 로짓의 정확 일치와 첫 바이트 예측에서 두 새 경로로 가는 기울기를 CPU에서 확인한 뒤 학습한다. 원문 복사와 디노이징은 0회다.

C: 여유 100GiB를 보호한다. 학습 시작 기준은 110GiB, 중지 기준은 101GiB이며, 체크포인트를 쓰기 전에는 파일 크기를 함께 계산한다.

데이터와 코드 점검 원시 기록은 fdt_local_102m_20261026/runs/three_memory_codec_20261111_v45/root_code_data_audit_20261111.json에 저장했다.

V46은 2,048회 시도에서 2,047회 업데이트를 완료했다. 보존한 V45의 91개 Adam 상태에 새 위치 파라미터의 상태 1개가 더해졌다. 최종 체크포인트와 종료를 독립 확인했다. C: 여유는 마지막 측정에서 136.519GiB였다.

| 비교 지표 | V45 | V46 |
| --- | ---: | ---: |
| 개발 256구간 바이트·종료기호 정확도 | 81.85% | 82.05% |
| 개발 256구간 기호당 손실 | 0.59974 | 0.60493 |
| 기존 학습 64구간 완전 복원 | 25 | 27 |
| 기존 개발 16구간 완전 복원 | 0 | 0 |

넓힌 개발 64구간의 완전 복원은 0건이었다. 64쌍을 직접 대조했으며, 정확한 인명이나 함수 식별자, 수치와 사건 관계가 복원 중 바뀌었다. 기존 개발 16구간의 평균 첫 일치 구간은 5.44바이트로 같았다. 위치 태그를 학습한 V46에서 두 슬롯의 순서를 바꾸면 첫 바이트 로짓 차이가 최대 0.806이었고, 태그를 끄면 0.0000062였다. 위치를 구분하는 경로는 생겼으며 문장 복원 완료 기준은 여전히 충족되지 않았다.

개발 문서를 끝까지 대조하자 기존에 뽑은 학습 1구간과 미선택 개발 문장 1개가 정규화상 일치했다. 보호해야 할 약어 뒤가 이어지는 후보는 기존 학습 152구간, 개발 256구간 중 9구간이었다. 이 가운데 개발 64구간에 포함된 3개를 교체했다. 새 자료에서는 약어 경계 후보 152개, 정규화 중복 1개, 개발 문서와 일치한 1개를 바꾸었다. 학습 154구간과 개발 3구간의 출처, UTF-8, 종료기호, 분리 상태를 독립 확인했다. 기존 평가 자료도 버전 간 비교에 사용할 수 있도록 보존했다.

학습 참고 복원 1건에서 잘못된 UTF-8이 발생했다. 새 디코더는 불법 시작 바이트와 이어지는 바이트를 제외하고, 문자가 중간에 끊긴 상태에서는 종료기호를 고르지 않는다. 실제 V46 체크포인트로 기존 오류를 CPU에서 재현한 뒤, 일반 복원 API에서 정상 UTF-8과 자연 종료기호를 확인했다. 정확히 복원되던 비교 문장도 그대로였다. 이 수정은 복원문의 바이트 형식을 보장하며, 오류가 났던 문장의 원래 뜻은 여전히 복원해야 한다.

다음 회차는 정리한 자료와 UTF-8 디코더를 실제 학습·복원 경로에 연결하고, 첫 오답을 줄이도록 초반 바이트 손실에 가중치를 주는 실험을 진행한다. 효과는 기존 평가와 경계를 정리한 개발 평가에서 함께 본다. 기존 30분 재개 예약이 활성 상태다.

V47은 경계를 정리한 자료와 UTF-8 제한을 실제 학습·복원 경로에 넣고, 처음 16자리의 손실에 4배 가중치를 줬다. 2,048회 모두 업데이트했고, 92개 Adam 상태의 연속성과 체크포인트를 검증했다.

| 같은 평가 자료 | V46 | V47 |
| --- | ---: | ---: |
| 개발 256구간, 처음 16바이트 정확도 | 86.06% | 89.77% |
| 개발 256구간, 이후 기호 정확도 | 81.19% | 80.28% |
| 개발 256구간, 전체 기호당 손실 | 0.60493 | 0.61573 |
| 기존 개발 64구간, 첫 오답 전 일치 바이트 평균 | 9.70 | 12.95 |
| 기존 개발 64구간, 정확 복원 | 0 | 0 |

경계를 고친 개발 패널에서도 정확 복원은 0/64였다. 직접 대조한 결과, 초반에 더 길게 맞은 문장에서도 뒷부분의 인명·관계·숫자가 달라졌다. 학습 참고 64건, 기존 개발 64건, 교체 개발 3건의 생성 출력은 모두 정상 UTF-8과 자연 종료기호를 갖췄다. 기존 학습 참고 문장의 정확 복원은 27건에서 24건으로 줄었다.

V48 후보는 기존 의미 벡터 2개와 세 메모리를 유지하고, 문장 위치별로 최대 16바이트를 요약한 퍼지 벡터 8개를 추가한다. 디코더가 출력 위치에 가까운 요약을 읽는 경로를 만들었다. 실제 V47 체크포인트에서 새 경로의 초기 가중치를 0으로 두면 로짓이 정확히 같았고, 앞·뒤 위치의 예측에서 새 경로로 기울기가 전달됐다. K_C를 끄면 추가 경로가 비활성화되며, 한 바이트 입력과 직렬화한 Commit도 CPU 검사를 통과했다. 같은 V47 학습 자료와 손실로 GPU에서 비교한다.
