# V70 영어 사실 보존 학습 결과 — 2026-11-12

ROOT가 이전 실패·성공 이력과 V69 원시 결과를 읽고, 수량·이름의 보존을 목표로 **실제 언어 인코더→퍼지 메모리→언어 출력기 512회 학습**을 완료했다. 준비 문서나 별도 역할 head 학습을 실제 언어 사이클 개선으로 대신하지 않았다. 이후 모든 프로세스 종료를 확인하고 저장된 출력과 fullstate를 독립 검토했다.

학습 상한 약 16배인 26만 바이트 두 입력에서 수량 필드 손상은 **51→20곳**, 실제 출력 바이트 차이는 **367→157개**로 줄었다. 그러나 다른 유효 숫자로 바뀐 사례는6→7곳, 인물명 변경은15→17곳이며 일부 기존 문장의 시간·이름 표현도 퇴행했다. **수량 보존의 긍정 결과와 남은 손실을 함께 보존한다.** 전체 언어→의미→언어 완성·일괄 승격으로 선언하거나 디퓨전을 시작하지 않았다.

## 무엇을 바꿨는가

V67의 같은 123,497,080개 파라미터를 모두 복사했다. 실제 활성 언어 인코더 마지막 두 층·value·condition과 출력기17,677,856개 파라미터를 학습했다. 기본 퍼지 K_P와 문맥 퍼지 K_C, Exact K_E의 경계는 유지하고 K_E는 최신 사람 지시대로 휴면 NULL이다. Exact에 이름/숫자를 넣거나 복사해 점수를 올리지 않았다. 디코더는 Commit만 읽었다. 원문 H/정답 prefix/정답 길이/골드 역할/span을 추론 feature로 주지 않았다.

기존 balanced CE·어려운 위치·tail EOS 손실에 **TRAIN 이름/숫자 구간의 평균 CE×0.25**를 추가했다. 구간은 원문을 인코딩하고 실제 Commit을 통해 logits를 만든 다음 훈련 손실에서만 사용한다. 이 계수는 제한 실험용 가설이며 최적값이라고 주장하지 않는다. 추론 모듈과 파라미터는 추가하지 않았다.

TRAIN은 새로 저술한384행과 기존 허용 OWT128행의 한 유한 epoch다. 총940,237 UTF-8바이트, 중요 구간38,480바이트로 이름20,213/숫자18,267바이트다. 16개 출력 위치별 역할에서 모두 훈련 노출을 확인했다. 평가 문장을 훈련에 편입하지 않았다. 표현 가족은 의도적으로 확장했으므로 예전 개발 형식 전체가 계속 미학습인 것처럼 부르지 않는다. 새32행의 이름8개는 전체 TRAIN에서 출현0이었다. 문서·문법 반복이 있어 독립512개 의미나 일반 언어 능력으로 확대하지 않는다.

초기 CPU 자료의 사용하지 않는 temporal annotation 일부가 실제 시간 관계를 말하지 않는 절에도 붙어 있는 것을 발견했다. revision2에서는 해당 label을 제외했다. TRAIN/DEV 실제 문장과 순서는 revision1과 SHA가 같으며 이전 자료와 builder도 보존했다. GPU 학습은 수정한 revision2로만 한 번 실행했다.

참고한 [개체 수준 사실 충실성 연구](https://aclanthology.org/2021.eacl-main.235/)는 개체 오류를 따로 다룰 근거이며 현재 loss의 효과를 보장하지 않는다. [숫자 토큰 손실 연구](https://arxiv.org/abs/2411.02083)는 수치 관계를 학습하는 대안을 제시한다. 이번 과제는 원문 수량을 보존해야 하므로 7을6으로 바꾼 것을 ‘가까운 수’라는 이유로 정답 처리하지 않았고, 회귀 오차만으로 대체하지 않았다.
