# V67 영어 의미 보존 중심 검토 — 2026-11-12

최신 사람 지시인 **“전체 일치에 과도하게 집착하지 말고 의미 정확도를 중시, 한국어는 제외하고 영어에 집중”**을 반영했다. 앞으로 영어 입력의 행위자·대상·관계·부정·수량·시간·순서·내용 누락을 주지표로 삼는다. 바이트 정확도와 전체 문자열 일치는 보조 진단이다. 한국어를 다음 학습·평가의 통과 조건으로 요구하지 않는다.

## 실제 영어 의미 판독

이전 V66에서 작성한 뒤 학습에 넣지 않은 영어 단문 24개와 장문 12개를 V67에서 다시 확인했다. 이미 관측한 평가 자료이므로 새로운 blind benchmark는 아니다. V67 TRAIN 1,024행과 전체 V66 평가 52행의 포함 관계를 CPU에서 확인했고, 평가 문장을 학습에 편입하지 않았다.

| 대상 | 의미 보존 검토 | 별도로 남긴 위험 |
|---|---|---|
| 영어 단문 24개 | ROOT가 원문·출력 전체를 대조해 24개 모두 핵심 명제 유지로 판독 | 2개는 `At`의 t 누락, 1개는 끝 공백. 문법·표기 문제는 남지만 시간·주체·행동·이동 방향 등은 유지 |
| 영어 장문 12개 | 제한된 작성 형식의 사건 묶음 244개 중 243개는 핵심 필드 유지 | 1개 사건에서 인물명 `Inez→IneV`로 참조 대상 불확실 |
| 장문의 기록 참조 | 사건 의미와 구분해 별도로 확인 | 기록번호 `2→&`, `53→[3` 두 곳 손상 |

단문은 ROOT의 입력 대비 출력 수동 판독이며 독립된 여러 평가자의 정답 라벨이 아니다. 장문은 작성된 ledger 문법에 한정한 CPU 사후 필드 비교다. 한 사건 묶음에는 행위자·수량·물건·남겨진 수량과 위치·검사자·검사와 이동의 순서·목적지·문 상태·부정이 포함된다. 반복되는 문장 틀과 필드는 상관되어 있어 244개의 독립 자연문서나 “범용 의미 정확도 99.6%”로 표현하지 않는다. 서로 다른 출력의 자연스러운 의역을 이 parser가 일반적으로 판단할 수도 없다. 문법 밖의 의역은 수동 검토 대상으로 두며 자동 오답으로 처리하지 않는다.

### 문자열이 달라도 의미가 유지된 사례

입력:

> At 6:45 on Tuesday, Alton moved three blue folders from the lower shelf to the upper drawer.

출력:

> A  6:45 on Tuesday, Alton moved three blue folders from the lower shelf to the upper drawer.

`t`가 공백으로 바뀌어 문법적 결함은 있지만 **6:45·Tuesday·Alton·공책 세 개·아래 선반에서 위 서랍으로 이동**한 내용은 모두 남아 있다. 반대 이동 방향 문장도 같은 내용 보존을 확인했다. 끝 공백만 추가된 사진 문장도 의미 실패로 세지 않았다.

이 밖에 주는 사람과 받는 사람 교환, `No visitor`/`One visitor`, `lighter`/`heavier`, eleven/four 수량 교환, before/after 순서 및 금액 42.75/47.25가 포함된 단문들의 입력 내용을 확인했다. 원문 대비 의미 보존을 보는 것이며, 원문 자체가 실제 세계에서 사실인지 판정한 것은 아니다.

### 남은 의미·참조 위험

긴 문맥의 `Inez placed ...`가 `IneV placed ...`로 바뀐 한 곳은 동일 인물이라고 자동 정정해 주지 않았다. 문맥상 오탈자로 읽힐 여지가 있지만, 출력 자체의 인물 식별은 불확실하다. 기록번호도 사용자가 특정 기록을 지칭할 때 중요할 수 있으므로 사건 수량·관계가 유지됐다는 이유로 누락하지 않았다.

기존 OWT 관측 개발 문맥에는 여전히 날짜의 `2016` 마지막 숫자 누락, `U-24→1-24`, 인명·약칭 손상, 1인칭 `I` 누락 등이 보인다. 따라서 제한된 새 작성 문장에서는 영어 의미 왕복이 관측됐다고 말할 수 있지만, 긴 자연문서의 모든 의미가 보존된다고 일반화할 수 없다. 단순 공백·인용부호 오류와 인물·수량·주체·날짜의 손상을 다르게 취급한다.

## 실행 결과와 보조 지표

V67은 최신 의미 우선 지시가 도착하기 전에 봉인된 복원 개선 실행이다. 실행 기록이나 목적을 소급 수정하지 않았다. 평균 CE가 숨기는 희소 바이트 오류와 마지막 구간의 잘못된 EOS를 줄이기 위해 기존 균형 CE에 hard-byte loss 및 tail false-EOS unlikelihood를 추가했다. 앞으로 같은 문자 중심 목적을 자동으로 반복하지 않는다.

- 실제 1,024 attempt / 1,024 update / AMP skip 0, worker 489.373초.
- encode 1,076 + readout 1,080 = 2,156회. 새 1,200초/2,200호출 한도 종료. 미사용 44호출과 시간은 재사용하지 않는다.
- TRAIN 1,024행 / 고유 원문 1,011개 / 한 유한 epoch / target 7,978,178 UTF-8 바이트. 길이 27~16,384바이트.
- 마지막 위치에 EOS를 고르게 학습할 수 있도록 약 16KB TRAIN 문맥 240개에서 16가지 byte remainder를 각각 15번 포함했다. 입력 문맥의 끝을 다루며 원래 문서의 진짜 끝이라고 주장하지 않는다.
- 기존 개발 문맥 16개: byte/EOS 99.7825→99.8469%, NLL .0108477→.00779666, 문자열 전체 일치 3→5/16.
- 학습하지 않은 관측 영어 36개: byte/EOS 99.9660→99.9876%, 최종 출력 바이트 위치 일치율 99.9907%, 문자열 전체 일치 28→31/36. 이 수치가 위 의미 판독을 대신하지 않는다.
- 기존 개발 문맥 raw 오류 142→100. 대문자 26→25, 소문자 30→9, 기타 82→61로 줄었으나 숫자는 4→5로 증가했다. 교정 63개 위치/새 오류 21개 위치다.

학습 범위·loss·ragged-tail 자료가 함께 달라졌으므로 특정 항 하나의 인과 효과로 주장하지 않는다. 한국어를 이번 V67에서 다시 학습하거나 평가하지 않았다.

## 메모리·추론 경계

동일한 **언어 인코더→기본 퍼지 K_P와 문맥 퍼지 K_C→CodecCommit→언어 디코더** 경로다. Exact K_E는 현재 유효 내용 0인 휴면 NULL 상태이며, 향후 명시적인 정확 복사 요청에만 내부 정책으로 사용한다는 사람 지시를 유지했다. 자동 원문 저장·코드포인트 색인·정답 prefix·원문 H의 디코더 우회·복사 바이트는 0이다. 의미 디노이징도 0이다. K_P의 인증된 writer/통합은 아직 구현되지 않았다.

사건 parser와 사람이 정리한 의미 카드들은 **저장 출력의 CPU 사후 평가 전용**이다. NN 추론 입력이나 학습 feature로 넣지 않았고, 고정 답변 템플릿·문자열 교정기로 언어 출력을 생성하지 않았다. 현재 복원기는 위치별 퍼지 정보도 보존하므로 이 결과만으로 추상 의미 공간이 유일하게 식별되거나 독립 의미 추론이 완성됐다고 하지 않는다.

## 검증과 보존

독립 감독자가 worker의 자연 종료를 10:18:08 KST에 기록했다. ROOT의 마지막 실행 중 관측은 10:17:02의 update 932였고, 이후 사용자 지시/heartbeat가 들어온 뒤 ROOT가 12:31:24에 모든 소유 PID 16828/16632/8280/28616 종료와 Python 0을 확인한 다음 분석했다. ROOT가 10:18에 직접 종료를 관측했다고 소급 주장하지 않는다.

초기/1/512/1024 네 fullstate의 SHA·safeload·재귀 digest, 30개 Adam state의 step 1024, scaler 1024/tracker 1024, 저장된 모든 RNG, order/cursor/history/exposure, 동결 prior 및 변경된 인코더·디코더를 CPU에서 확인했다. 새 loss의 hard-k·tail mask·loss 구성과 TRAIN 노출도 확인했다. 기존 개발 raw 32개 및 현재 영어 raw 36개를 저장 logits부터 다시 읽고 argmax·정답·UTF-8 제약/EOS·최종 문장을 확인했다. 추가 모델 호출 0, CUDA 초기화 false였다.

CPU 검토의 이전 float32 NLL 합 비교 허용오차가 일부 행에서 너무 작았다. 원 오류·검토 코드를 보존하고 모든 argmax/문자열/정답 수가 동일함을 확인한 뒤, 합에 한해 float32 epsilon 기반 허용오차를 적용했다. worker·가중치·실제 출력은 수정하지 않았고 GPU를 다시 실행하지 않았다.

최종 fullstate 635,811,399바이트, SHA `b47c9bdf920605b153c1ebfaa31a28579eb35c1784de6037ba54f4674cdc18b9`, algorithm SHA `d8b2ba555605913d38415bf7dc427b16f50245e34b542e5f91c831f059b6cd20`. Plan SHA `65b840546b25eed14a32e784bd562e0ccbeb71f941d51231fa2c877b0dd32b16`.

현재 모델 프로세스는 없으며 C: 여유 약 123GiB로 100GiB 보호 기준을 지켰다. 모든 기존 source/weights/Adam/scaler/RNG/raw/실패를 보존했다. 에이전트·E2 final/registry·외부 게시·유료 cloud 사용은 0이다.
