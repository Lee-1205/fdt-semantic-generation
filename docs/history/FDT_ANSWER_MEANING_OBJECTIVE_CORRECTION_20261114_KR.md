# 디노이저의 목표 정정: 입력 의미에서 답변 의미 생성

2026-11-14. 최신 사람 지시를 ROOT가 직접 반영했다. 에이전트·새 모델 실행·새 optimizer update는 모두 0이다.

**디노이저의 본래 목적은 입력 의미를 그대로 복원하는 것이 아니라, 입력 의미와 허용된 메모리를 조건으로 답변이 될 새로운 의미를 형성하는 것이다.** 앞선 답변의 “다음 핵심도 원래 의미의 복원”이라는 방향은 이 목표를 잘못 좁혔다. V109/V110 identity 복원 실험은 구조와 학습 경로의 병목을 분리한 보조 진단으로 보존하며, 주 학습 목표를 대신하지 않는다.

## 학습과 추론의 경계

```text
입력 언어 X → 고정 추출 E → 입력 의미 Zx
                              │
          독립 잡음 + K_P 기본 퍼지 + K_C 입력별 퍼지 + 허용된 K_E
                              │
                     디노이저 Rθ 반복
                              │
                   최종 답변 의미 Z_answer 확정
                              │
                         고정 언어화 D
                              │
                           답변 언어

훈련 때만: 정답 답변 Y → 같은 고정 E → 의미 표적 Zy=E(Y)
           Rθ의 최종 답변 의미를 Zy에 맞춘다.
```

- 입력 조건은 `Zx=E(X)`다. **주 표적은 `Zy=E(Y)`이며 `E(X)`가 아니다.** 이 단계에서는 손실을 통해 θ만 학습하고, 기존 입력·메모리 형성·결합·출력의 가중치 및 buffer는 고정한다.
- 정답 답변 의미·정답 원문·정답 역할·정답 길이·정답 mask는 훈련 손실 쪽에만 둔다. 실제 추론의 디노이저에는 제공하지 않는다. 언어 출력은 최종 의미가 확정된 다음에 한다.
- K_P/K_C는 기존 의미·퍼지 메모리 경로를 유지한다. K_E는 현재 정책대로 invalid NULL/content0/copy0다. 일반 문장을 Exact에 담아 꺼내는 복사 학습으로 바꾸지 않는다.
- “새 의미 생성”은 입력과 관계없는 내용을 무작위로 만드는 성공 기준이 아니다. 질문·사실·메모리에 맞는 답변의 내용이 형성되어야 한다. 답변 관계, 방향, 부정, 불확실성을 실제 문장에서 확인하고 전체 문자열 일치와 구분한다.

## 기존 자료를 올바른 표적과 연결한 CPU 계약

새 산출물은 `fdt_local_102m_20261026/research/artifacts/answer_meaning_objective_20261114_v1`이다.

1. 기존 V108의 엄격한 입력 왕복 통과 TRAIN 134개를 유지했다. 다른 자료나 DEV를 새로 편입하지 않았다.
2. 기존 V95 TRAIN의 원래 질문-답변 관계로 결합했다. **134개 모두 입력 원문과 답변 원문이 다르며, TRAIN 답변 의미는 27종**이다. 이는 134개의 독립 사실 또는 27종의 범용 사고 능력을 의미하지 않는다.
3. `train_conditions.json`은 입력 ID와 source-only 의미 참조만 담는다. `train_targets_LOSS_ONLY.json`은 해당 ID에 연결된 원래 정답 답변 의미 참조와 훈련 전용 원문을 별도로 담는다. 하나의 파일 전체를 NN 입력으로 넣는 계약이 아니다.
4. 기존 134개 source 의미 파일과 사용한 27개 답변 의미 파일의 SHA를 검증했다. tensor 재인코딩·복사·모델 forward·학습은 0이다. 계약 SHA는 `f938065fbc90daaebc4ef7ac70536a8ab7ee02d14334e1dea2d6bf41cf741f9a`다.

이는 **CPU JSON 결합 및 목표 정정**이지 새 디노이저 학습 완료나 실행 가능한 봉인 plan이 아니다. V110의 full-span velocity 구조 수정은 유지할 가치가 있지만, identity runner를 이름만 바꿔 실행하지 않는다. 실제 다음 worker는 답변 의미 표적을 소비하도록 바꾸고 기존 전체 fullstate·RNG·동결·시간/호출/노출 상한·owned OS 감독 계약을 유지해야 한다.

## 기존 답변 의미의 출력 검사에 관한 주의

기존 V95 `target_index_loss_only.json`의 31개 답변은 정답 문장 prefix가 모두 맞지만, 과거 capacity33 출력에서 정답 뒤 잡음이 붙어 전체 문자열 exact는 0이다. 이는 이번 새 모델 평가가 아니라 저장 JSON 조회 결과다. 이후 identity 통제의 capacity35 및 terminal 정렬과 같은 조건이라고 간주해서는 안 된다.

그러므로 다음 실제 답변 의미 학습에서 **표적 packing·고정 capacity·terminal/EOS의 일치**를 실제 worker preflight에서 구분해야 한다. 과거 31개 문자열 exact0만으로 답변 의미 정보가 없다고 하거나 모두 탈락시키지 않는다. 반대로 올바른 prefix만으로 완전한 언어화가 검증됐다고 하지도 않는다. 입력을 복사하는 identity 학습을 오래 계속하는 방식은 이 답변 표적 문제의 해결이 아니다.

V109/V110 결과·실패·가중치·Adam/scaler/RNG와 기존 V102/V105 관계 생성 분기는 모두 보존한다. 두 identity trial의 시간·호출·노출 예산은 닫힌 상태이며 재사용하지 않는다. 타이머 삭제 상태를 유지한다.
