## 자료·출력의 해석

승인된 기존 OWT TRAIN 자료에서 짧은 문장·중간 문맥·긴 문맥 128행, 고유 원문 124개를 선택했다. 39~16,384 UTF-8 바이트 범위를 유지했다. 두 유한 epoch, 256행 선택, target 1,117,008 UTF-8 바이트와 EOS 256개다. DEV 16개는 기존 128~16,384바이트 문맥을 변경하지 않았다. 원문 단위 TRAIN/DEV 중복 0, 모든 선택 문맥이 기존 TRAIN 원문의 연속 부분임을 CPU에서 독립 확인했다. 잘린 입력 문맥의 끝을 복원하는 것이며 원래 전체 문서의 끝을 예측했다고 주장하지 않는다.

출력은 target prefix나 원문 H를 디코더에 주지 않고 Commit만으로 만들었다. 다만 16바이트 단위 위치별 퍼지 기여를 보존하는 구조적 codec이며, Commit의 대략적인 문맥 길이와 기존 조기 EOS 방지 규칙을 유지한다. 임의의 추상 의미가 유일하게 식별됐거나 새 문장 길이까지 자율 결정했다는 증거는 아니다. 높은 복원 정확도만으로 일반 의미 이해나 정보 손실 0을 가정하지 않는다.

ROOT는 저장된 출력과 원문 차이를 직접 읽었다. 128바이트 두 문맥과 256바이트 한 문맥은 완전히 같았다. 나머지 문맥은 대체로 긴 문장 흐름을 유지하지만, 다음과 같이 의미 정밀도에 영향을 주는 오류가 있다.

- 1,024바이트 문맥에서 날짜의 숫자가 줄바꿈으로, 통화 기호가 숫자로 바뀌었다.
- 2,048바이트 문맥에서 `AS10`이 `ASH0`으로 바뀌어 지시 대상을 손상했다.
- 4,096바이트 문맥에서 `U-24`가 `1-24`로, 인명 이니셜이 다른 글자로 바뀌었다.
- 8,192바이트 문맥의 수량 표기와 인명, 16,384바이트 문맥의 이름·주소·기호·페이지 숫자에도 오류가 남았다.

이는 초기의 제한된 학습에서 해결할 잔여 오류다. 전체 설계의 실패로 단정하지 않는다. 문자 유사도와 단어 중복 F1은 보조 지표이며 위 사실 오류를 상쇄하는 의미 동치 점수가 아니다. 실제 비교 전문과 차이는 `root_reading_similarity.json`에 저장했다. 현재는 완벽한 문장 복원 완료라고 하지 않는다.

최종 네 문맥의 퍼지 Commit 내용을 0으로 만들면 worker가 기록한 NLL은 정상 조건보다 크게 증가했다. 대략적인 Commit 길이 구조는 남겼다. 이는 현재 출력이 퍼지 상태의 수치 내용에 의존함을 지지하는 제한된 통제다. 해당 통제의 raw logits는 저장하지 않았으므로 CPU raw 재계산 결과로 세지 않는다. 올바른 추상 의미만을 독립적으로 사용한다는 인과 증명도 아니다.
