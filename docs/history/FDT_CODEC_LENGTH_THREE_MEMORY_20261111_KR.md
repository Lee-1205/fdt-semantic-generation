# 긴 문맥과 세 메모리: 실제 결과와 현재 학습

2026-11-11 ROOT 직접 수행. 사람의 길이 우선 답변은 **문장·문맥 길이 우선**이다. 에이전트는 사용하지 않았다. 원래 언어→의미→같은 입력 언어 복원 단계이며 의미 디노이징과 자동 원문 복사는 실행하지 않는다.

## 길이 확장

기존 입력128바이트/출력129기호 제한을 제거했다. 동결된 원래 계층과 학습된 가중치를 보존하고, 처음129개 위치와 그 Adam 상태도 그대로 가져왔다. 새 위치만 별도 파라미터로 학습한다. 문맥 퍼지는16바이트마다 순서 있는 지역 슬롯을 만든다. 디코더는 Commit만 읽고, 긴 출력은 검증한 KV 캐시 경로를 사용한다.

실제 GPU 순전파·역전파 측정에서16384바이트가 설정한12GiB 이내였다(최대7799705600B). 24576바이트는13448846848B로 한도를 넘었다. 따라서16384바이트를 현재 실측 학습 상한으로 삼았다. 이는 UTF8바이트이며 토큰 수나 전역 하드웨어 최대치, 정보 무손실 증명이 아니다. 첫 설정 수정과 FP16 scaled-gradient overflow를 별도 기록으로 남겼고, BF16에서 유한 기울기를 확인했다. 정밀도 선택의 참고자료는 [PyTorch AMP 문서](https://docs.pytorch.org/docs/stable/amp.html)다.

## 메모리 각각의 실제 확인

- K_E: 원문 바이트와 SHA, 모든 UTF8 codepoint span의 연속 분할, top16+NULL 확률 정규화, stale index 거부를128→16384바이트8개 사례에서 확인했다. 저장이 정확하다는 사실과 디코더의 정확한 literal 선택은 구분한다.
- K_C: 같은8개 입력의 FP64 long/recent N/D를 별도의 순차 recurrence로 전부 재구성해 일치시켰다. 개별로 끄면 복원 NLL이 크게 상승한다.
- K_P: 기본 퍼지 prior 읽기를 유지했다. 현재는 learned prior이며 certified writer/consolidation까지 구현·검증됐다는 뜻은 아니다. 읽기 경로는 있으나 복원에 대한 추가 기여는 작다.

V50에서는 지역 슬롯이 K_C만 읽고 K_P/K_E는 두 전역 슬롯에만 들어갔다. V52는 각 지역 슬롯에서도 K_P anchor-prior와 주변 codepoint K_E top16+NULL을 읽도록 보완했다. 정답 span·원문 바이트·raw H를 디코더로 넘기지 않는다. 새 gate는0에서 시작해 기존 출력과 일치하며, 학습 기울기와 각 은행의 분리를 CPU에서 확인했다.

동일8개 개발 입력의 byte수 가중 비활성화 결과는 V52 r2에서 K_C NLL+10.33418, K_E+0.062514, K_P+0.000151이다. Exact 활용은 증가했지만 기본 prior의 효과는 아직 작다. 같은 관측 개발 표본과 후속 학습·설계 변경의 결과이므로 각 수정의 독립 인과효과나 모든 입력에서의 효과로 확정하지 않는다.

## 직접 읽은 복원문

128/512/2048/8192바이트 네 원문과 복원문을 읽었다. V52 r2는 모두 원래 바이트 길이에서 자연 종료했지만 Canada/Slims River, Idaho/Otter/Aaron Paul, Savarkar와 연도, 장문 논지와 세부 내용이 정확하게 보존되지 않았다. 반복·철자 혼합도 남았다. 단순 유사도나 teacher NLL을 의미 보존 성공으로 세지 않는다. 길이 복원은 진전이며 완벽한 문장 복원은 아직 달성하지 않았다.

## 완료 V53

8192개 원래 TRAIN 문서 전체의 최대16384바이트 입력 창을 한 유한 epoch로 학습한다. 새 노출40416999UTF8바이트, 실제 문서 끝7859개/길이 상한에 의한 입력 창333개다. 입력 창 EOS와 문서 EOF를 구분했다. 원래 DEV 분할은 유지했으며 새로운 다운로드/최종 holdout 접근은 없다.

목적은 학습량 확대와 정답 접두어 의존 감소다. 손실의 절반은 clean AR CE, 나머지 절반은 모든 이전 정답 바이트를 PAD로 가린 복원 CE다. 추론은 기존 Commit-only 경로를 유지한다. 세 메모리와96개 Adam/scaler/RNG를 그대로 이어가며 새 파라미터는0개다. 별도 memory-only 위치별 복원 정확도도 기록한다.

CPU에서 정답 문장을 바꿔도 마스킹된 접두어가 같음을 확인했고, enabled scaler/AMP skip/마지막7행/복구 후 다음 업데이트를 검사했다. 실제 전체 크기 CPU engine 복구도 통과했다.

실제로8192시도/8192업데이트/skip0,3731.561초,8232encode+44825decoder=53057호출로 완료했다. 원래7200초/100000호출 예산은 종료됐으며 남은 시간을 재사용하지 않는다. 모든25616/21444/39452/39756 소유 프로세스가 종료된 뒤 분석했다.

## 당시 다음 문제 (V54 실행 전 기록)

teacher 향상만으로 Commit의 내용이 언어로 복원된다고 판단할 수 없다. 먼저 V53 encoder/세 메모리를 동결한 채 공유된 소규모 patch readout을 학습해, 같은 Commit에서 표면 순서가 복원 가능한지 AR 경로와 분리한다. 현재16바이트 지역 요약에는 명시적인 구간 내부 위치 결합이 없으므로, 이 readout도 부족하면 그때 순서 결합을 보완한다. encoder가 원래 순서 정보를 전혀 담지 않는다는 단독 증명은 아니다. 이 후속은 아직 GPU 실행하지 않았다.

이전 V7/V46의 위치 구분 문제와 V53의 낮은 memory-only 성능을 우선 근거로 삼았다. [BLT의 local encoder/decoder](https://aclanthology.org/2025.acl-long.453.pdf)는 byte↔patch 접점을 분리하는 설계 참고다. FDT 전체를 해당 모델로 교체하거나 원문 우회 경로를 도입한다는 뜻은 아니다.

## V54: 같은 Commit의 별도 언어화 실험 완료

V53 인코더와 세 메모리를 모두 동결하고2,908,192개 파라미터의 공유 patch readout만 학습했다. 같은 TRAIN 중512문서, 같은 관측 DEV16이며3624/3624업데이트,skip0,4200호출,126.036초로 완료했다. 모든 소유 프로세스 종료 후3개 head 복구본과528개 문서 cache,전체 raw logits를 CPU 독립 검토했다. 원래96Adam/scaler/RNG는 필수 부모에 보존되며 새 head는 별도의 fresh Adam이다.

정답 접두어 없는 정확도22.0013%,NLL2.213306이다. 같은 Commit을 다른 입력과 교환하면7.4032%/6.429513으로 떨어진다. 입력별 정보가 남아 있다는 증거지만 충분한 의미 보존이나 완벽한 디코딩의 증거는 아니다. 원문·복원문4개를 모두 읽었고 이름·주장 보존은 미달이다.

별도로 EOS loss 가중치가 지나친 조기 종료에 영향을 주는 문제를 계산했다. 실제 TRAIN 배치에서 EOS의 평균 유효 가중치278.207161,log-bias5.628366을 얻었다. 저장 logits에서 그 값만 빼면 false-positive EOS253→1,precision5.95→91.67%였지만 본문 정확도는22.07%에 머물렀다. DEV에서 최적값을 고른 것이 아니며 근사 보정 후보다. [logit adjustment 연구](https://research.google/pubs/long-tail-learning-via-logit-adjustment/)는 이런 분포 보정의 참고이며 이번 수치의 최적성을 보장하지 않는다. 원본 결과는 보존했다.

V55는 같은 퍼지 N/D 읽기를16개 입력 위치별 기여로 나누고 공유256→32 projection을 거쳐16개 부분공간에 결합하는 후속 후보다. 위치별 기여의 합은 기존 지역 퍼지 요약과 같다. K_P/K_E와 원래 전역·지역 Commit은 유지한다. 원문 바이트·raw H·정답 접두어를 언어화에 넘기지 않는다. 인코더 전체가 순서 정보를 전혀 담지 않는다는 주장은 하지 않는다. 새 projection과 readout만 학습하고 EOS 과잉 가중치를 제거하는 별도 한정 실험이다. CPU 후보 검사는 통과했으며 준비를 GPU 학습이나 성능 향상으로 세지 않는다.
