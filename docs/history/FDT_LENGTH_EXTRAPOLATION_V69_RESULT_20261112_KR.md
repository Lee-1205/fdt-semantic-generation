# 학습 길이 밖 영어 복원 V69 결과 — 2026-11-12

학습 최대 16,384 UTF-8바이트를 유지한 같은 V67 가중치로 약 2·4·8·16배 길이까지 실제 시험했다. 최대 입력은 **262,042바이트**였고, 262,029바이트를 하나의 긴 문장으로 만든 조건도 끝까지 출력했다. 새 학습·옵티마이저·의미 디노이징은 모두 0회다.

긴 입력을 처리하는 실행 경로는 확보했다. 다만 수량과 인물 표기가 일부 손상되므로 **언어→의미→언어의 의미 충실성 전체를 완료로 판정하지 않았다.** 디퓨전으로 자동 진입하지 않는다. 이것은 연구 전체의 실패 판정이 아니라 이번 입력에서 확인한 남은 수정 범위다.

## 실제 입력과 결과

문서와 단일 장문을 각 길이에서 하나씩 사용했다. 각각 새로 작성한 사건 기록이며 같은 문법의 상관된 반복 사례다. 정식 RULER/RHELM 점수나 자연 문서 전체의 의미 정확도로 해석하지 않는다. 이 모델은 바이트 입력이므로 아래 길이는 BPE 토큰 수가 아니다.

| 학습 상한 대비 | 문서 실제 바이트 | 단일 문장 실제 바이트 | 문서의 보수적 표면 사실 보존 | 단일 문장의 보수적 표면 사실 보존 |
|---|---:|---:|---:|---:|
| 약 1배 | 16,201 | 16,287 | 83/84 사건 | 78/85 사건 |
| 약 2배 | 32,649 | 32,664 | 165/169 | 158/170 |
| 약 4배 | 65,357 | 65,441 | 330/339 | 304/341 |
| 약 8배 | 130,913 | 130,906 | 648/678 | 617/681 |
| 약 16배 | 262,042 | 262,029 | 1,305/1,356 | 1,222/1,362 |

표의 보존 수는 사건의 인물·수량·물건·출발/도착 위치·순서·부정 및 관계 표현에 표면 변경이 없거나 사건 번호만 달라진 수다. **나머지를 모두 의미 오답으로 센 값이 아니다.** `before→bebore`, `remove→remoxe`, `drawer→draber`처럼 문맥에서 뜻을 읽을 수 있는 철자 흠도 별도 검토 대상으로 빠져 있다. 따라서 일반 의미 정확도 수치로 인용하면 안 된다.

총 1,014,489바이트/5,265개 상관 사건을 사후 비교했다. 이 기준에서 4,910개는 핵심 필드와 관계 표현이 유지됐고, 151개는 필드 표기 검토, 204개는 관계 단어/형식 검토 대상이다. 모든 10개 입력에서 UTF-8 및 EOS가 정상이고 출력 바이트 길이는 입력과 같았다. 실제 디코딩 결과의 바이트 차이는 총 676개였다. 바이트 유사도는 보조 지표이며 아래 내용 손상을 대신하지 못한다.

## 직접 읽어 확인한 내용

앞·중간·끝의 실제 source-output 사건 30쌍과 모든 변경 필드의 종류, 반복되는 철자 흠, 관계 단어/형식 변경을 읽었다. 번호별 원문과 출력 전체 및 모든 변경 사건은 raw와 별도 JSON에 남겼다. 수정한 정답 문장을 실제 모델 출력으로 대체하지 않았다.

- 수량/잔여 수량 필드의 변경 85건 중 **9건은 다른 유효 숫자로 바뀌었다.** `18→15`, `28→24`, `28→25`가 실제로 있었다. 나머지는 숫자가 문자/기호가 되는 등 수량을 확정하기 어려운 변경이다. 이는 단순 띄어쓰기와 구별해야 한다.
- 인물명 필드는 22곳에서 표기가 바뀌었다. `Cyril→9yril/myril`, `Fiora→Viora` 등을 같은 인물이라고 자동 교정하지 않았다.
- `before→bebore` 29곳은 `before→after` 전환과 구별된다. 주변 문맥에서 읽을 수 있는 표기 흠으로 검토하되 출력 표기를 고쳐서 점수를 올리지 않았다.
- 단일 장문은 이미 16K 범위 안에서도 문서 형식보다 철자 흠이 많았다. 긴 길이에서만 갑자기 모든 내용이 붕괴하는 양상은 관측되지 않았으며, 형식/국소 위치/수량·이름 재현의 문제를 길이 문제와 함께 분리해 다룰 필요가 있다. 문서와 단일 문장은 다른 사실 표본이므로 형식이 유일 원인이라고 확정하지 않는다.
- 처음·중간·끝과 계산 경계를 가로지르는 사건에서도 다수의 보존을 확인했다. 특정 위치 일부만 읽고 문서 전체 의미 보존이라고 선언하지 않았다.

## 코드에서 해결한 길이 병목

기존 언어 Transformer는 48바이트 인과 국소 주의를 쓰지만 길이 전체의 NxN 마스크를 만들었다. 새 실행 경로는 2,048바이트씩 계산하면서 각 층의 앞 47개 K/V와 절대 RoPE 위치를 이어 간다. **문서 전체 global pool, 장기/최근 퍼지 N/D와 한 개의 전체 Commit**은 유지한다. 독립 구간별 출력물을 이어 붙이는 방식으로 바꾸지 않았다.

가중치/위치 테이블을 늘리거나 재학습하지 않았다. 실제 사용 중인 언어 출력은 ordered fuzzy patch readout이고, 보존 중인 옛 AR decoder의 길이 테이블은 이 경로에서 사용하지 않는다. 고정 logits의 UTF-8 출력도 사용하지 않는 긴 prefix를 매번 재복사하던 부분을 제거해 같은 선택을 선형 시간으로 처리했다.

CPU 작은 모델 및 실제 크기 모델의 짧은 입력 동치, 전체 부모 상태 복구를 확인했다. 실제 GPU 4,096바이트 두 입력에서도 기존 계산 대 분할 계산의 argmax가 전부 같았고, Commit 상대 L2 약 2.6e-7, logits 약 9.1e-8, 장기/최근 N/D 약 2.4e-7이었다. 그 다음 길이 시험을 수행했다.

**중요한 범위:** 국소 퍼지 Commit의 저장량은 입력 길이에 비례해 늘어난다. 고정 크기 의미 벡터로 임의 길이를 무손실 압축한 증거가 아니다. 기존 48바이트 주의가 전역 주의로 바뀐 것도 아니며, 먼 두 사실을 결합하는 추론·질의 응답 능력은 이번 복원 시험으로 검증되지 않았다. 표현이 다른 동의 문장을 같은 의미로 처리하고 역할/부정/수량 변화를 구별하는 문제도 별도 증거가 더 필요하다.

K_P 기본 퍼지 prior 읽기와 K_C 문맥 퍼지는 유지했다. K_E Exact는 최신 사람 지시대로 휴면 NULL이며 원문·숫자·이름을 Exact에 자동 저장하거나 복사하지 않았다. 디코더에는 Commit만 전달하고 원문 H/문자열/정답 prefix/정답 출력 길이를 넣지 않았다. K_P의 인증된 새 지식 writer/consolidation은 아직 구현된 것으로 주장하지 않는다.

## 후속 연구 범위

이번 시험으로 긴 입력 실행 제한과 분할 경계 연속성은 해결했다. 다음은 **수량/이름의 의미 충실성 및 다른 표현 사이 실제 퍼지 의미 상태의 일관성**을 보완하는 별도 한정 학습이다. V69의 실제 평가 문장/정답은 TRAIN에 넣지 않는다. 기존 V59–V62의 pre-bank head 우회와 현재 Commit-only 경계를 유지하고, 의미 head 점수만 개선해 언어 사이클 완료로 세지 않는다.

V68의 CPU 초안은 아직 실행하지 않았다. global Commit 전체를 paraphrase 불변으로 만드는 loss와 그 global만으로 가려진 원문 표현을 그대로 복원하라는 loss 사이 충돌 가능성을 먼저 정리한다. 형태 보존용 로컬 퍼지 정보 전체를 무조건 같은 벡터로 붕괴시키지 않는다. 수량·인물 표기 우선 자료/학습과 의미 불변성 학습을 필요에 따라 분리한다. 현재 언어→의미→언어를 충분히 확보한 뒤 별도 의미 디노이징 단계로 넘어간다는 사람의 순서를 유지한다.
