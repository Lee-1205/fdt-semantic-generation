# V91에서 새 오류가 늘어난 직접 원인

**이번 장문 오류3개는 공유된 마지막 출력 분류기의 Adam 업데이트가 기존의 좁은 정답 경계를 넘긴 결과다.** 같은 저장 의미 Commit과 같은 동결 prefix를 사용해 마지막2개 tensor만 바꾸었을 때 세 오류가 모두 재현됐다. 입력·퍼지 memory·binding이 이번 업데이트에서 변해서 생긴 오류가 아니다. 이것이 의미 추출 전체가 완벽하다는 뜻은 아니다.

사람의 최신 지시대로 추가 학습·GPU 평가·새 padding 실험 준비를 중단하고 기존 저장본만 조사했다. 전체123M 모델을 구성하지 않았다. 바뀐4지점(새 오류3+대문자 교정1)의 prefix4회, 해당 byte role의258-class 출력16회만 CPU로 계산했다. 실제 계산0.922초, encoder0/denoise0/optimizer0/GPU0이다. 전체194개나 장문 전체를 다시 생성하지 않았다.

## 같은 입력에서 바뀐 결정 경계

숫자는 해당 지점의 `정답 글자 점수 − 실제 오답 글자 점수`다. 양수일 때 정답이 앞서고 음수가 되면 오답이 앞선다.

| 새 오류 | V88 | V91 | 변한 양 |
|---|---:|---:|---:|
| `drawer`: w→b | +0.000458 | −0.012142 | −0.012600 |
| `episode`: s→t | +0.001129 | −0.005398 | −0.006527 |
| `remove`: v→x | +0.003410 | −0.020184 | −0.023594 |

저장된 실제 GPU argmax와 이번 CPU 부분 계산의 argmax가4지점 모두 일치했다. weight 변화와 같은 hidden feature의 내적으로 계산한 점수 차이도 실제 차이와 약2.4e-6~1.3e-5 안에서 일치한다. 세 오류의 학습에 의한 점수 이동은 이 수치 차이보다 훨씬 크다. 따라서 새 오류를 FP32 반올림 탓으로 돌릴 근거가 없다.

각 오류에서 **정답·오답 두 class row만 V88 값으로 되돌리는 오프라인 대조**를 하자 세 지점 모두 원래 정답을 다시 골랐다. 나머지 V91 class row는 유지했다. 여섯 번의 weight decay만 적용한 대조에서는 세 오류가 발생하지 않았다. 실제 학습 업데이트에 의한 class 간 상대 점수 변화가 필요했다.

또한 수락된6회 보정의 실제 class 목록을 조사했다. 새로 틀린 세 쌍의 class row 여섯 개는 **방향 보정이 직접 건드린 행이 한 개도 없었다.** 해당 행은 원래 Adam 학습 변화로 이동했다. 보정의 직접 행 수정이 세 오류를 만든 것으로 해석해서도 안 된다. 중간6개 weight/gradient는 저장하지 않았으므로 어느 한 attempt·훈련 행·loss 항이 유일한 원인인지는 특정하지 않는다.

오프라인 row 복원은 원인 진단이다. 이를 가중치에 저장하거나 모든 문장에서 안전한 수정이라고 선언하지 않았다.

## 왜 보호 검사가 통과했는가

마지막 출력층의 class row는 같은 byte role의 모든 문맥에서 공유된다. 일부 TRAIN 문장의 loss를 줄이는 업데이트가 다른 문장의 상대 점수를 동시에 바꿀 수 있다. 문제가 된 장문 세 지점은 이미 V88에서도 정답 우위가0.000458~0.003410으로 작았다.

보호 검사는 고정 TRAIN의7,623개 feature patch와119,769개 top1,152개 취약 critical floor에 한정됐다. 이 TRAIN 원문의 최대 길이는16,384UTF8 byte였고, 이번 장문은약262KB다. 세 문제 지점의 hidden feature와 정확히 같은 feature는 그 bank에0개였다. 길이 차이만이 유일한 원인이라는 주장은 하지 않는다. 실제로 검사하지 않은 문맥의 결정을 보호한다고 보장할 수 없다는 뜻이다.

정답 글자와 byte role이 같은 보호 TRAIN 지점 중 수치적으로 가까운 지점도 살폈다. 이 지점들의 최종 정답 우위는 약11.5~12.9로 여전히 컸다. 같은 class row가 약간 이동해도 이 TRAIN 지점은 맞지만, 장문에서 우위가 매우 작은 지점은 뒤집힐 수 있다. 따라서 TRAIN 위반0과 장문 새 오류3이 동시에 성립한다. 보호 장치가 전체 문장 보존 장치인 것으로 취급된 범위 문제가 드러난 것이다.

전용 critical 규칙은 주로 숫자·이름을 다룬다. 새로 손상된 `drawer`, `episode`, `remove`의 일반 어휘 byte를 그 자체로 모두 보호하는 규칙은 아니다. 일반 byte의 top1 보호도 유한 TRAIN bank에만 적용됐다. 숫자·일부 TRAIN 지점을 지키는 것과 모든 일반어를 안정적으로 언어화하는 것은 별도의 요구다.

## 앞서 조사한 수치 여유 문제와의 구분

padding1e-6보다 큰 FP32 잔차는 **보정한 업데이트57개가 다시 거부된 현상**을 설명하는 증거다. 이번에 **수락된 업데이트 이후 장문 오류3개가 늘어난 직접 원인**은 위에서 재현한 공유 분류기의 학습 간섭이다. 수치 padding만 바꿔 더 많은 업데이트를 통과시키는 실험을 우선하면 이 간섭 문제를 해결하지 못한다. 해당 실험은 시작하지 않았다.

V91을 승격하지 않는 기존 결정을 유지한다. V88을 분석 기준으로 남기며 모든 복구 가중치·Adam/RNG·실패 원문을 보존했다. 다음 수정의 초점은 일반어와 긴 문맥에 대한 공유 출력층의 간섭 및 보호 범위다. 관측한 장문 정답을 TRAIN에 넣거나, 실제 정답을 보고 inference에서 글자를 교체하는 방식은 사용하지 않는다.
