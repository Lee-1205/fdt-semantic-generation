# FDT 출력 퇴행 원인 분리와 수치 경로 수정 — 2026-11-13

추가 SGD 대신 과거 코드·원시 출력·동일 메모리를 대조했다. **일부 오류는 출력 계산 정밀도, 확인한 퇴행 5곳은 마지막 출력층의 학습 변화로 설명된다.** 의미 추출이나 Diffusion 전체의 실패로 묶어 판단할 근거는 없다. 문장→의미→문장 전체가 완성됐다는 증거도 아직 아니다.

## 1. 실제 수행과 범위

- V71의 메모리/출력 교차 실험, V74의 동일 Commit 출력기 개선, V75~V80의 퇴행과 개선을 먼저 읽었다. 과거에 고친 오류를 이번에 처음 발생한 오류로 세지 않았다.
- V81: 이미 관측한 12개 바이트 사례, 고유 Commit 11개. V75/V80의 고정 출력기와 정밀도 4조건, 같은 B 사실을 유지하며 A만 바꾼 짝의 local/global 교환을 **133회 읽기 전용 호출**로 조사했다. 실제 작업 3.146초, 최대 GPU 메모리 약 805MiB. 기존 native 출력의 관심 바이트를 **12/12 재현**했다.
- V82: 고정 FP32 수정 경로를 기존 64개 Commit 전체에서 **64회 읽기 전용 호출**로 확인했다. 실제 작업 5.730초. 새로운 문장이나 새로운 독립 benchmark가 아니다.
- 실제 GPU 출력기 호출 합계 197회. CPU 사전 복구 검사에서는 실제 크기 출력기를 합계 4회 실행했다. **새 입력 인코더 호출 0 / optimizer 0 / 디노이징 0 / 새 가중치 체크포인트 0.** 작은 CPU 계약 검사는 7개 통과했다.
- 두 실행 모두 별도 120초/종료 여유 30초와 호출·출력 상한을 사전 고정했다. 각각 worker/owner exit 0, ROOT가 모든 native/proxy 종료와 Python 0을 먼저 확인한 뒤 결과를 분석했다. 미사용 호출·시간은 닫았다.
- 가중치, 부모 Adam/scaler/RNG, 원본 자료·과거 실패·게임은 보존했다. 마지막 확인 C: 116,175,720,448B, 약 108.20GiB. 삭제하지 않았다.

## 2. 확인된 첫 원인: 저정밀 출력 판정

같은 Commit과 같은 V80 가중치를 유지하고 계산만 바꿨다.

| 조건 | 관심 바이트의 `5` 대 최강 오답 점수 차이 | 출력 |
|---|---:|---|
| 기존 전체 BF16 | -0.25 | `7:` |
| BF16 prefix + 마지막 Linear FP32 | +0.03957 | `75` |
| 전체 출력기 FP32 | +0.02959 | `75` |

출력 후에 `.float()`로 변환하는 것은 이미 사라진 점수 차이를 복구하지 못한다. 수정 코드는 출력기 연산 자체에서 autocast를 끄며, prefix와 마지막 Linear를 모두 FP32로 계산한다. TF32도 끈다. 입력 추출, 의미 메모리, 가중치 및 파라미터 이름은 바꾸지 않았다. PyTorch의 공식 [AMP 문서](https://docs.pytorch.org/docs/stable/amp.html)와 [수치 정확도 문서](https://docs.pytorch.org/docs/main/notes/numerical_accuracy.html)가 설명하는 정밀도 경계에 따른 조치다. 문서가 이 모델의 원인을 입증하는 것은 아니며, 위 동일 조건 실험이 해당 사례의 근거다.

수정 인터페이스: `research/readout_precision_policy_v81.py`. 입력은 neural Commit뿐이다. 정답, 원문, 정답 길이, 사후 문자열 교정, Exact 검색, 사례별 정답 의존 정밀도 선택은 사용하지 않는다.

같은 64문장에서 검증한 결과:

| 지표 | 기존 BF16 | 고정 FP32 |
|---|---:|---:|
| 원시 byte/EOS 오답 / 15,584위치 | 25 | 24 |
| 기존 정답에서 새로 생긴 오답 | — | 0 |
| B 수치·단위 명확 보존 | 51/64 | 52/64 |
| B 명확한 값 변경 | 4 | 4 |
| 숫자 핵심은 남지만 비표준 접두사가 붙어 의미 미인증 | 8 | 8 |
| `75→7:` 숫자 손상 | 1 | 0 |
| UTF8/EOS | 64/64 | 64/64 |
| 완전 일치 — 보조 지표 | 43/64 | 44/64 |
| byte NLL | 0.0068071958 | 0.0068121099 |

**NLL은 아주 조금 나빠졌다.** 따라서 모든 지표가 개선됐다고 보고하지 않는다. 의미에 중요한 숫자 한 곳은 복구됐고 나머지 63개 출력은 바이트 단위로 동일하다. 이 패널 밖의 무퇴행을 보장하는 결과도 아니다.

ROOT가 실제로 전체 원문과 수정 전·후 출력을 읽었다. 원문의 사실은 ‘Blythe가 확인한 잔여 재고 **75 copper washers**, Alaric의 별도 입고 **34 copper washers**’다. 수정 전에는 잔여 재고가 `7:`였고, 수정 후 `75`가 됐다. 별도 입고 34와 다른 내용은 그대로다. 단순히 문장을 보기 좋게 다듬은 것이 아니라 숫자 정보 한 곳을 복구한 결과다.

## 3. 더 큰 잔여 원인: 마지막 출력층의 결정 경계 이동

V75와 V80의 입력·메모리·결합부와 출력기 prefix 5개 tensor가 동일함을 확인했다. 같은 저장 Commit에 두 출력기를 연결하고 FP32 계산을 통일하면, 마지막 Linear 2개 tensor의 변화만 남는다.

| 관측 사례 | V75 정답 마진 | V80 정답 마진 | 변화 |
|---|---:|---:|---|
| 새 패널 28, `+` | +0.22851 | -0.42611 | `+→#` |
| 새 패널 29, `+` | +0.15158 | -0.49865 | `+→#` |
| 긴 문서 0, episode1174 수량 첫 글자 | +0.38092 | -0.23978 | `26→+6` |
| 긴 문서 1, episode1299 수량 첫 글자 | +0.03089 | -0.13130 | `7→&` |
| 긴 문서 1, episode1336 인명 첫 글자 | +0.09298 | -0.18501 | `Fiora→2iora` |

이 5곳에서는 **동일 메모리를 V75 출력기는 올바르게 읽었고 V80 출력기는 잘못 읽었다.** 해당 퇴행을 입력 의미가 새로 손실됐기 때문이라고 설명할 수 없다. 마지막 출력층의 변경이 충분한 원인이다. 예를 들어 첫 행의 마진 변화 -0.65462 중 bias 기여는 약 -0.00042이고, 대부분은 weight×동일 hidden의 변화다. 단순 출력 bias 한 값을 수정하는 방법도 충분하지 않다.

정밀도만 고쳐 남은 문제까지 해결하지는 못했다. 강하게 틀리는 짧은 사례와 원래 FP32로 계산했던 긴 문서 오류는 그대로다. 이 표는 목적을 정해 고른 관측 사례이며 전체 실패 중 5건의 비율을 추정하는 표가 아니다.

## 4. 왜 단순 반복 학습·일괄 되돌리기가 답이 아닌가

동일 prefix를 유지하면 마지막 Linear 파라미터를 V75→V80으로 보간했을 때 각 logit은 α의 선형 함수다. 저장된 모든 258개 클래스 점수에서 정답 제약을 직접 계산했다.

- 새 패널 8을 올바르게 고치려면 **α ≥ 0.571627**이 필요하다.
- 새 패널 28의 기존 정답을 유지하려면 **α ≤ 0.349073**이어야 한다.
- 두 구간은 겹치지 않는다. 같은 업데이트 방향을 단순 축소하거나 두 체크포인트를 전역 비율 하나로 섞어 이 두 사례를 동시에 해결할 수 없다.

이는 관측 개발 사례에 대한 진단 계산이다. 이 α를 개발 정답으로 고르거나 학습 selector로 쓰지 않았다. V80에 유용한 개선도 있어 무조건 버리거나 전체 V75로 소급 덮어쓰지도 않았다. 두 버전과 모든 상태를 보존했다. 필요한 것은 다른 학습 방향과 실제 보존 조건이며, ‘같은 학습을 더 돌리면 된다’는 근거는 없다.

## 5. V80 보존 장치와 자료의 한계

V80의 장치는 TRAIN 100개 기준에서 처음 맞았던 byte의 top1이 유지되는지만 확인했다. 해당 장치가 보고한 ‘기준 안의 정답 손실 0’은 사실이다. 그러나 점수 차이가 `1.0→0.01`로 줄어도 top1이 같으면 통과한다. 전체 TRAIN 1,024개, 기준 밖 문장, 새로운 장문까지 보존한다는 뜻이 아니다. 이번 퇴행은 그 한계와 양립한다.

이를 보완하는 `research/train_margin_retention_v81.py`를 별도 작성했다. 미래 TRAIN 기준에 대해서 top1과 초기 정답 마진의 제한된 비율을 함께 보호하는 후보다. 초기 오답은 고쳐질 수 있고 PAD는 보호 대상에서 제외한다. 수치 정밀도가 일치하지 않으면 거부한다. 위 `1.0→0.01` 반례를 실제 CPU 검사에서 차단했다.

**이 후보는 CPU 계약 검증까지이며 새 optimizer driver에 적용해 학습한 결과는 없다.** 모든 미학습 사례의 보존을 보장하지 않는다. 다음 실행에서 전체 FP32 출력 정책을 쓴다면 TRAIN prefix feature도 같은 정밀도로 만들어야 한다. 기존 BF16 feature bank를 그대로 사용하면서 동일 조건이라고 주장하면 안 된다.

자료를 좁게 재검토한 결과:

- TRAIN은 숫자 896개 view와 OWT128개다. 기준 bank는 숫자84개+OWT16개다. 84개 부호/폭 cell을 덮어도 모든 문맥·숫자·위치의 결합을 덮지 않는다.
- B 시작 byte role은 TRAIN과 기준 bank 모두 16개 전체가 있다. ‘해당 byte 위치를 한 번도 학습하지 않았다’는 단순 설명은 맞지 않는다.
- A/B 부호는 독립적으로 변하지만 정수 자릿수는 `(1,1)` 320행, `(2,2)` 288행, `(3,3)` 288행으로 묶여 있다. 서로 다른 자릿수 조합은 빠져 있다.
- 다만 이번 개발 64개는 모두 `(2,2)`다. 따라서 위 혼합 자릿수 공백을 이번 퇴행의 입증된 원인이라고 부르면 안 된다. 후속 일반화 자료에서 고칠 별도 한계다.
- 이번 관측 개발 prompt와 TRAIN literal 중복은 0이다. 기존 split을 유지했고 관측 개발 문장·정답을 TRAIN에 넣지 않았다.

## 6. 이번에 지지되지 않은 설명과 남은 불확실성

- 현재 출력기는 `CommitPatchReadout` MLP다. 예전 DIANA 계열 AR 파라미터는 이 출력 경로에서 사용하지 않는다. 현재 오류를 AR의 반복 피드백 때문으로 단정하지 않는다.
- 같은 B를 유지하고 다른 A의 global/local 메모리를 교환한 9개 사례에서 B 판정이 뒤집히지 않았다. 이 조건에서는 다른 A의 메모리가 B를 직접 뒤집는 간섭 가설을 지지하지 않는다. 메모리 전체에 간섭이 없다는 뜻은 아니다.
- global을 0으로 만들면 여러 사례가 악화됐다. 이는 비정상 메모리 입력 통제이며, global 제거를 수정안으로 채택할 근거가 아니다.
- bound Commit에는 입력 인코더와 역할 결합이 함께 들어 있다. 저장된 이 tensor만으로 두 과정을 다시 분리할 수 없다. 과거 V71에는 상류 원인 사례도 있었으므로 ‘항상 출력기만 문제’라고 결론 내리지 않는다.
- 일부 같은 Commit이 V75 출력기로 읽힌다는 것은 해당 정보가 읽힐 수 있다는 증거다. 장문의 모든 의미가 추상 의미 공간에서 완전 보존된다는 증거는 아니다.
- K_P prior와 K_C 동적 fuzzy 경로는 유지했다. K_E는 현재 NULL/content0/copy0이며 평문 전체 복사 경로를 만들지 않았다. K_P의 인증된 writer/consolidation까지 완성됐다는 주장은 하지 않는다.

## 7. 다음 작업 기준

현재 원인을 구분하지 못한 채 동일 SGD를 반복하는 경로는 중단했다. 수치 출력 수정은 구현·제한 검증했고, 남은 출력 경계 퇴행에 대해서는 다음 한정 학습의 목적을 분명히 한다: 같은 정밀도의 TRAIN feature/margin 보존, 기준100개 밖의 실제 TRAIN coverage, A/B 값·자릿수·predicate 문맥의 독립성. 개발 정답을 보호 bank나 학습 목표에 편입하지 않는다. 전체 기존 평가를 무한 선행조건으로 반복하지 않는다.

다음 실제 학습은 이 원인에 대응하는 새 driver·자료·고정 비용을 검토한 별도 실행이어야 한다. 현재 새 SGD와 Diffusion 학습은 하지 않았다. 언어→의미→언어가 안정되기 전 Diffusion으로 자동 승격하지 않으며, 이후 사고 부분을 학습할 때는 입력·메모리·결합·출력 전체 가중치와 buffer를 고정한다.
