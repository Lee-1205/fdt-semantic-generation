# V77: update 비중 보정으로 일부 회복, 장문 보존은 V75 미회복

2026-11-13 ROOT가 새 한정 학습을 완료하고 모든 owned/proxy 종료를 확인한 뒤 저장 상태·출력·실제 문장을 검토했다. **V77을 기본 후보로 승격하지 않고 다음 학습의 초기 기준은 V75로 유지한다.** V76 대비 장문 수량 오류는 일부 회복됐지만 사건번호 손상은 늘었다. 전체 언어→의미→언어 구조의 실패나 학습 가능성의 부정으로 해석하지 않는다.

## 무엇을 실제로 학습했나

V75에서 출발해 출력기 7개 tensor/2,908,192파라미터만 fresh AdamW LR1e-5로 학습했다. 전체 NN은 123,497,080파라미터이며 상류 언어 추출·퍼지 결합은 고정했다. 같은 1,024개 TRAIN 원문을 teacher 단계에서 한 번씩 읽고, head 단계는 부호 문장 768행×1, 부호 없는 문장 128행×6, 같은 OWT 128행×3으로 총 1,920회 노출했다. 실제 순서는 unsigned/signed/OWT/unsigned/signed의 384유한 cycle, update 비중 40/40/20이다. 1,920개의 새 문서나 1,024행의 단일 epoch라고 부르지 않는다.

Teacher 원문은 1,010,943 UTF-8바이트, head 원문 노출은 2,720,189바이트, 중요구간은 86,108바이트다. V75의 258개 base symbol weight를 그대로 고정했고 숫자 weight는 3.64954로 유지했다. V76의 오답 중요 CE cap8은 유지했다. 행 비중을 맞췄다는 것은 clip/Adam 이후 파라미터 gradient 기여가 정확히 같은 비중이라는 보장은 아니다. 학습 횟수·노출·weight가 함께 달라져 이번 단일 실험으로 원인을 하나로 확정할 수 없다.

원문→K_P 기본 퍼지/K_C 문맥 퍼지→bound Commit→언어 경계를 유지했다. K_E Exact는 invalid NULL/내용0/복사0이며 Decoder에 원문 H/rawbyte, gold prefix/길이/역할을 주지 않았다. 추론·의미 디노이징은 0이다. K_P의 인증 장기 writer/통합은 아직 없으며 세 메모리 전체 기능 완성을 선언하지 않는다.

## 아주 긴 문장·문서는 어느 정도 유지됐나

실제 원문을 다시 처리한 것은 문서형262,042바이트/47,470공백단어와 한 긴 문장형262,029바이트/47,680단어다. TRAIN 최대16,384바이트의 약16배다. 두 출력 모두 전체 길이·UTF-8·EOS를 유지했고 원문의 앞·중간·끝6개 구간도 실제로 읽었다. fresh source Commit과 기존 동일 상류 Commit,4,096바이트 native/stream 처리의 parity를 검증했다.

전체2,718개 상관 사건, 수량·보관량5,436필드를 원문에 묶어 비교했다. V77의28개 수량 변화는 약0.515%이며 두 문서의 수량 필드5,408개는 같은 값을 유지했다. 이것은 수량 필드의 제한 문법 검사이며 문서의 모든 추상 의미 정확도99.485%라는 뜻이 아니다. 사건번호17개·이름2개·물품7개와 다른 표현 오류도 별도로 존재한다. 제한 문법의 before/after 순서·위치·부정 유무는 변화0이었다. 따라서 문맥 끝이 사라지거나 관계 구조 전체가 무너졌다는 과장은 피하면서, 국소 사실 손상은 계속 해결해야 한다.

## 추가 계산: 단순한 `+` bias 보정으로 충분한가

새 모델 forward 없이 V75/V76/V77의 저장 logits와 실제 최종 bias를 비교했다. 잘못된 `+` 출력은 장문 전체8→22→21개, 숫자를 `+`로 바꾼 것은8→20→21개다. V77의21개 중19개가16바이트 patch의 내부 위치12/13에 집중됐다. 수량 오류 일부가 회복됐어도 숫자/부호 간섭이 해결된 것은 아니다.

V75에서는 맞고 V77에서 `+`가 된12개 위치에서, `+` 대 gold 경쟁 logit 차이의 변화 중앙값은1.920780인데 최종 bias 차이의 변화 중앙값은0.001123이었다.12개 모두 bias 변화만으로 전체 경쟁 변화량을 설명할 수 없었다. 따라서 전역 `+` bias 하나를 깎는 것으로 해결된다고 단정하기 어렵다. 같은 local Commit을 읽는 위치별 조건부 readout 경로 변화가 주로 포함된다. 이 계산은 BF16로 반올림된 저장 logits와 bias의 산술 분해이며 파라미터 gradient/인과 매개 실험은 아니다. 새 신경망 호출·optimizer0이다.

상류 전체 tensor는 불변이고 수정64개의 Commit도 전후 비트 수준으로 같으므로, 이번 학습으로 새로 생긴 출력 변화는 readout에서 발생했다. 이것이 상류 의미 표현이 이미 완벽하다는 인증은 아니다. 기존 위치별 fuzzy role 결합을 보존했으며 의미 디노이징 실패로 돌리지 않는다.

## 코드 점검에서 발견한 plan 설명 필드 오류

기존 plan을 `dict(old)`로 계승하면서 V77의 설명용 `actual_trainable_parameters`가17,677,856으로 남고, 과거 출력 추정5,656,937,760/3,324,668,416바이트도 함께 남은 것을 사후 발견했다. 실제 optimizer 소유7개 tensor와 CPU gradient 점검·저장 fullstate에서 확인한 학습 수는2,908,192이며, 실제 guard/독립 검토가 사용한 최신 추정은1,104,832,864바이트/하드 cap1.25GiB였다. 실제 출력도 cap 이내다. **설명 필드 검증이 불충분했던 오류는 인정하고 원래 sealed plan을 보존한다.** 실행 상한이 커졌거나 실제 학습 대상이17M였다는 뜻은 아니다.

후속용 `plan_scope_contract_v78_cpu.py`는 실제 active tensor에서 scope를 계산하고 단일 출력 추정·정확한 call 합·100GiB+출력cap+8GiB headroom을 요구한다. 실제 V77의 오래된 필드를 거부하고 scope/count/합계/cap/headroom/call/상속 추정 재유입을 검출하는8개 CPU 검사에 통과했다. 이것은 향후 worker에 연결할 계약이며 V77 plan 소급 수정이나 V78 runner/plan/GPU 실행이 아니다.
