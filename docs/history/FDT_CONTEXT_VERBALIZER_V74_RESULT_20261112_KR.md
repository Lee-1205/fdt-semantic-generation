# V74 문맥 조합 출력기 학습과 미학습 영어 복원 결과

ROOT가 V74의 실제 **640attempt/640update/AMPskip0** 학습을 완료했다. V73의 언어 추출·퍼지 결합을 전부 고정하고 마지막 출력기7개 tensor/2,908,192파라미터만 학습했다. 전체 모델은123,497,080파라미터다. 결과는 **양수 수량의 내용 보존 개선과 기존 장문·자연문 보존의 퇴행**이 함께 있다. 언어→의미→언어 전체 완료를 선언하지 않으며 디노이징은 계속0이다.

이번의 핵심 비교는 학습 전후 상류가 완전히 같다는 것이다. 기존 관측 패널의 같은 bound Commit을 새 출력기로 읽어 수량을 더 정확하게 표현했다. 따라서 특정 오류를 개선하는 데 필요한 정보가 기존 추출·결합 상태에 있었다는 근거는 된다. 이것이 모든 추상 의미가 이미 완성됐거나 모든 오류가 출력기에만 있다는 증거는 아니다.

현재 입력 경로는 원문→언어 추출→K_P prior/K_C 문맥 퍼지→bound Commit→언어 출력이다. K_E Exact는 휴면 NULL/내용0/복사0이며 일반 문장·이름·숫자를 Exact에서 불러와 고치지 않는다. 출력기에 원문 H/바이트·정답 prefix·GT 길이·정답 역할을 주지 않았다. K_P의 인증된 장기 writer·통합 기능은 아직 없다. 길이에 따라 local Commit 저장량이 늘어나므로 고정 크기 의미 메모리의 무손실 압축이라고 부르지 않는다.

TRAIN640행은 새 작성512행/256개의 상관 부호 최소짝과 기존 OWT TRAIN128행이다. 한 유한 epoch의 실제 원문1,039,965 UTF-8바이트/중요 구간34,194바이트다. 주 수량은 `+kg/-kg/+degrees C/-degrees C` 각128개로 교차하고 이름 내부y/마지막z를 보강했다. 모든 기존 자료·분할을 보존했다. 새로운 DEV64행은 다른 문장 형식과 TRAIN에 없는 `Ilyaz/Kyrene/Anya/Ezrien`을 사용한다. 실제 held `Zephyr/Boaz`와 평가 문장은 TRAIN에 넣지 않았다. 자료 첫 준비에서 `Ezra`가 기존 OWT TRAIN에 있음을 발견해 실패 기록·builder를 보존하고 별도v2에서 `Ezrien`으로 수정했다. 제외 기준이나 기존 OWT를 줄여 통과시키지 않았다.
