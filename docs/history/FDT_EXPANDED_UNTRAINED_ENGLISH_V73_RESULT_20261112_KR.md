# V73 미학습 영어·장문 확장 검증 및 추출 학습 결과

2026-11-12. ROOT가 직접 **960attempt/960update/AMPskip0** 학습과 확장 검증을 완료했다. 출력기7개 tensor는 고정하고 실제 추출·퍼지 결합23개 tensor/14,769,664파라미터만 학습했다. 새 평가 입력도 원문에서 다시 인코딩했다. 이번 검증은 **미학습 영어128개와 장문10개**이며,장문 중8개는 새로 작성한 약32/64/128/256KiB 입력이다.

결과는 개선과 남은 문제가 함께 있다. 준비했던32개와 보존 패널은 나아졌지만,추가한96개의 새로운 표현에서는 개선 폭이 작고 새 이름·양수 kg 표현에 오류가 집중됐다. 긴 입력이 끝부분에서 잘려 사라지는 현상은 관측하지 않았지만,길이 유지가 의미 보존 완료를 뜻하지 않는다. 현재 언어 사이클 전체의 완성이나 추상 의미 공간의 무손실성을 선언하지 않으며 디노이징은0이다.

현재 경로는 원문→학습된 언어 추출→K_P prior/K_C 문맥 퍼지→bound Commit→고정 언어 readout이다. K_E Exact는 휴면 NULL/내용0/복사0이다. 일반 문장·이름·숫자를 Exact에서 꺼내 고치지 않았다. 출력기에 원문 H·바이트·정답 prefix·GT 길이·정답 역할을 주지 않는다. K_P의 인증된 장기 writer·통합 기능은 아직 없고 prior read만 유지한다. 위치 기여16개를 행위자 같은 추상 의미 역할로 바꿔 부르지 않는다.

TRAIN은 CPU에서 이미 검토한960행/1,392,317 UTF-8바이트/중요 구간39,730바이트의 한 유한 epoch다. 새 작성832행/416상관 최소짝과 기존 OWT TRAIN128행이다. V72의 전체123,497,080개 모델 파라미터를 정확히 복원하고 fresh23Adam을 사용했다. 원래V72의7Adam/scaler/모든RNG와 그 이전 모든 상태·실패는 보존했다. 초기 teacher960행의 확률·정답 여부·정답·mask만 loss 전용 packet으로 저장하고,학습960행에서는 **매번 원문을 실제 새로 인코딩**했다. 바뀌는 추출기 학습을 과거 Commit cache로 대체하지 않았다.

평가 자료는 TRAIN과 분리한 `fuzzy_extraction_eval_20261112_v73_cpu`다. 미리 준비한 미학습32행에 사람의 추가 지시 뒤 새96행을 더했고,기존 관측 장문2개에 새 장문8개를 추가했다. 새 장문은 문서형과 진짜 단일 긴 문장형을 각각32/64/128/256KiB 근처에서 만들었다. 최대262,131바이트로 TRAIN 최대16,384바이트의 약16배다. 새 이름8개는 현재 TRAIN에 없고,평가의 실제 prompt/gold를 훈련에 편입하지 않았다. 새 데이터 다운로드나 E2 final/registry 접근은0이다.

다만 새 입력은 작성 문장과 상관된 반복 사건 문법이다. 7,835개 사건 구간을 독립 자연 문서나 blind benchmark로 세지 않는다. 새로운96행도 과거 오류를 보고 설계한 것이며 범용 자연 영어의 독립 성능으로 확대하지 않는다. 자연 OWT16개는 과거부터 관측했던 보존 패널이고 이번에 처음 보는 자연 문서 시험은 아니다.

새 장문8개의 수량 구간 변화는18개,이름 구간 변화는453개였다. 수량은 이동량·잔량을 뜻하며,별도로 사건 번호20개도 변했다. 따라서18개를 모든 숫자의 오류 수로 부르지 않는다. 이름 변화442개가 `Zephyr`359개와 `Boaz`83개에 집중됐다. `Zephyr→Zepher/ZAphyr`, `Boaz→Boak`처럼 여러 위치에서 같은 이름의 철자가 달라지는 정체성 위험이다. 사람에게 유추 가능한 오타도 있지만 자동 교정해 성공으로 세지 않았다. 다른 새 이름과 관계·수량이 정상인 많은 구간도 함께 보존했다.

장문10개는 모두 원문과 같은 최종 바이트 길이/EOS/정상 UTF-8을 유지했다. 각 길이의 처음·중간·끝30개 구간을 읽었으며,수량·관계·방향이 유지되는 예와 이름·항목의 오타를 나눠 기록했다. 현재 패널에서는 길이 경계에서 갑자기 전체 출력이 무너지는 양상을 관측하지 않았다. 그러나 길이별 사실·이름 배치가 다르고 표본이 두 개씩이므로 길이의 순수 인과 효과나 고정 메모리 압축·장거리 추론 능력을 증명하지 않는다. local Commit 저장량은 입력 길이에 따라 늘어난다.

기존 관측 장문2개도 새 가중치로 원문 streaming을 다시 실행했다. V72→V73에서 수량 구간 변화는12→11이었지만 이름 변화는4→7로 늘었고,실제 decoded 오류는67→74였다. 이 퇴행을 보존했다. V72처럼 고정된 과거 Commit만 다시 읽고 새로운 추출 성능이라고 주장하지 않았다. 최종 가중치의 동일4096바이트 입력에 대해 FP32 native/stream Commit·argmax 실행 동등성도 실제 확인했다.

부정·긍정 표현은 source-bound 문법에서7,627구간이 정상 파싱됐고196구간은 같은 사건 안의 국소 표현으로 같은 polarity를 확인했다. regex 미해결12개를 ROOT가 전부 읽었는데 `did remoxe`, `fid not remove` 같은 오타였으며 원문에 있던 `not`의 유무는 남아 있었다. 이를 범용 부정 이해100%로 부르지 않는다. 같은 문맥의 이름 식별 손상은 별도 위험으로 남겼다.

추가 CPU 자료 점검으로 다음의 구체적 편중을 찾았다.
